# 内部预言机图解（原子矩阵枚举）

> **本文讲什么**：项目里"完备性预言机"是如何**推断（更准确说：穷举）异构体数目**的。
> 配套 4 张图在 `Instruction Data/oracle_figs/`。
>
> **代码位置**：`oxygen/atomic_matrix_gen.py`（C/H/O 系，`AtomicMatrixGenerator`）、
> `Nitrogen/atomic_matrix_n.py`（C/H/N 系，`AtomicMatrixNGenerator`）——两者同构，
> 只差原子类型与价态表（C=4 / O=2 / N=3）。

---

## 0. 一句话定位：它不是"估算"，是"穷举真值"

树机制生成器（`UnifiedOxoGenerator` / 生成树）**快但可能漏**；
预言机反过来——**在最底层的原子+键级层面穷举所有合法结构**，
再按同构去重，得到的就是该分子式在八隅律下的**数学真值**。
所以它被当作"完备性标尺"：树机制与它的差集 = 树机制的覆盖缺口。

![图1 流水线](<oracle_figs/fig1_pipeline.png>)

上图的等价关系是**全部剪枝的立足点**：

```
已用价 = Σ(每个键的键级)          H = Σ(原子价态) − 2 × 已用价
→  "H 数固定"  完全等价于  "所有键的键级总和固定" = valence_target / 2
```

---

## 1. 矩阵模型：把分子变成一排"格子"

拿 `N` 个重原子（nC + nO 或 nC + nN）排成上三角矩阵：
**位置数 = N(N−1)/2**，每个位置取值 `0..max_bond`（0=无键，1=单键，2=双键，3=三键）。

![图2 矩阵与手算实例](<oracle_figs/fig2_matrix.png>)

`max_bond` 由元素对决定（`_max_bond_type`）：**C–C → 3**（C≡C）、**含 O → 2**（C=O，
不承认 C≡O）、**O–O → 1**。

### 手算实例（与代码实测一致）

| | C₂H₇N | CH₅N |
|---|---|---|
| Σ原子价态 | 4+4+3 = **11** | 4+3 = **7** |
| 目标 H | 7 | 5 |
| `valence_target` = Σ价态 − H | **4** | **2** |
| ⇒ Σ键级 = target/2 | **2** | **1** |
| 位置数 | 3（C0–C1, C0–N2, C1–N2） | 1（C0–N1） |
| 合法且连通的组合 | 两条单键、且连通 ⇒ 2 种（乙胺 / 二甲胺） | 1 种（甲胺） |
| **异构体数** | **2** | **1** |

> 正是 `python -m Nitrogen.validate --anchors` 里 C2H7N=2、CH5N=1 的来源。

## 2. 回溯搜索 + 四道剪枝（边搜边砍）

![图3 回溯与剪枝](<oracle_figs/fig3_backtrack.png>)

回溯按 `p0 → p1 → …` 顺序给每个位置试值；四道剪枝**都是精确判定**（只砍必错的分支，
不会丢结构）：

| # | 剪枝 | 判据 | 为什么精确 |
|---|---|---|---|
| ① | 目标键级超出 | `已用价 > valence_target` | 键级只增不减，之后永远超标 |
| ② | 到不了 | `已用价 + 剩余位置最大可贡献价 < valence_target` | 乐观上界都够不着 |
| ③ | 连通下界 | `非零键数 + 剩余位置数 < N−1` | 连通图至少 N−1 条边 |
| ④ | 孤立原子 | 某原子度=0 且已过其最后可连位置 | 它再也没机会连上 |

叶节点还要过三关：`Σ价 == 目标`、`所有原子都参与连通`、`BFS 验证图确实连通`。

## 3. 两个"不重不漏"的关键装置

![图4 有序生成与去重](<oracle_figs/fig4_dedup.png>)

**装置 A：有序生成** —— 同一个分子换个原子编号会有 `N!` 种矩阵（都是同一个图）。
规则：新原子首次成键必须是"**同类型内按索引递增的下一个**"（C 按 0..nC−1、O/N 接着排）；
两端都新的键放行，末端用"图是否连通"兜底。
效果：同一个图只走一条路径，实测 **C₆H₈O 317 s → 28 s（≈11×）**。

**装置 B：同构去重** —— 这才是"异构体"的定义：
① WL 图哈希分桶（快）→ ② 桶内 **VF2 全属性同构**确证（label + bond_type）。
必须有 ②：WL 哈希会碰撞（实测 `C1OC1C1CO1` 与 `C1OC2COC12` 同哈希），
只用哈希去重会**少算**结构。

## 4. 图解要素 ↔ 代码对照

| 图解要素 | 代码位置（`oxygen/atomic_matrix_gen.py`） |
|---|---|
| 原子列表 / 价态 / 总价 | `__init__`: `atom_types` / `valences` / `total_valence` |
| 位置编号 p0…p(N(N−1)/2−1) | `_position_to_indices()`（row-major 上三角） |
| 每位置最大键级 | `_max_bond_type(a1, a2)` |
| `valence_target` | `rem = total_valence − target_h; valence_target = rem` |
| 剪枝①②③④ | `backtrack()` 开头的三个 `return` + `bt == 0` 分支里的孤立原子判定 |
| 有序生成前缀规则 | `if not (i_new and j_new): … i != n_conn_c …` |
| 叶节点三关 | `used_valence != valence_target` / `n_conn_c+n_conn_o != N` / `_is_graph_connected(M, N)` |
| 去重① | `_wl_hash_graph(M, atom_types)` → `seen` 字典 |
| 去重② | `_seen_add()` + `_matrix_graphs_isomorphic()`（VF2） |
| **异构体数** | `len(results)`（唯一图个数） |

> N 系（`Nitrogen/atomic_matrix_n.py`）同构：`atom_types = ['C']*nC + ['N']*nN`、
> `valences = [4/3]`，另多一条"O–O 不超过 1 键"式的快剪枝。

## 5. 规模与耗时（实测，本机 11 核）

| 分子式 | 重原子 | 唯一结构数 | 耗时 | 说明 |
|---|---|---|---|---|
| C₄H₆O₂ | 6 | 263 | 0.9 s | 预言机与树机制在此规模已对齐 |
| C₆H₅N | 7 | 4 394 | 70.9 s | 含环/多重键组合爆炸 |
| C₇H₅N | 8 | 30 478 | 1 839 s | 已属"要等"的量级 |
| C₈H₁₅N | 9 | 12 770 | ~5 400 s | 外推：每加一个重原子约 ×10 |
| C₉ 及以上 | ≥10 | — | 数十小时 | 故 GUI 设 `_N_MAX_ATOMS = 10` |

**为什么慢**：原子级穷举**不跳过**任何"化学上紧张/反芳香"的合法结构（这正是"完备"的代价），
搜索空间随重原子数近似指数增长。

## 6. 常见疑问

**Q：为什么它和 MAYGEN 的计数有时不一致？**
A：两种原因（均已用图级同构核验过）——① MAYGEN 的 `.smi` 输出含**重复行**，其计数按行统计；
② 同一分子的**不同凯库勒式/芳香化书写**会使 SMILES 字符串不同。
我们的判据是"**缺失 = 0**"：MAYGEN 有的，我方一个都不缺。

**Q：为什么要用它当"边界标尺"，而不是直接用它生成？**
A：它慢（见上表）。所以主流程用树机制快速产出 98%+ 的结构，**用预言机来度量缺口**；
只有含氮体系例外——实测"预言机比树机制更快且完备"，故 N 系直接以预言机为主生成器。

**Q：`_MAX_ATOMS` 能不能调大？**
A：可以，但见上表：10 重原子已是"数十小时"量级。真正的提速方向是
**预言机并行化**或**更强的对称性剪枝**（有序生成已带来 11×）。
